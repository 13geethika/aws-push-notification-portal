CHANGES LOG: SERVERLESS UPGRADE (API GATEWAY + SQS DLQ + LAMBDA IaC)
====================================================================

This log details the complete architectural transition of the AWS Push Notification Portal. The infrastructure is now fully serverless and managed via AWS CloudFormation.

---

1. ARCHITECTURAL FLOW COMPARISON
--------------------------------
* Current Client-Server Model (Spring Boot):
  React Client -> Spring Boot (local / ngrok) -> SQS -> SQS Worker Lambda -> SNS -> FCM.
  (Uses a local Java web server as a gateway proxy to AWS).

* Modern Event-Driven Serverless Model (API Gateway + SQS DLQ):
  React Client -> API Gateway (REST HTTP endpoint)
                     ↓
             PushApiLambda (restructures routes, loads Firebase config, enqueues SQS)
                     ↓
             Main SQS Queue ('push-notification-queue')
                     ↓ (triggers)
             PushNotificationWorker Lambda (SNS endpoint mapping & publish pushes)
                     ↓
                  Success -> SNS -> FCM -> Browser
                     ↓
                  Failure -> Retries (Up to 3 times) -> Dead-Letter Queue ('push-notification-dlq')

---

2. FILE CHANGES LOG
-------------------
* template.yml (CloudFormation Template):
  - Rewritten from scratch to declare all AWS resources in a single stack file:
    1. 'PushNotificationDLQ': A dedicated SQS queue that isolates failed messages for troubleshooting.
    2. 'PushNotificationQueue': The main SQS queue, integrated with the DLQ Redrive Policy (maxReceiveCount: 3).
    3. 'PushLambdaExecutionRole': Single IAM execution role with permissions for SQS polling, SQS writing, SNS publishing, and CloudWatch logging.
    4. 'PushApiLambda': Exposes Node.js serverless REST handlers for config serving, register mocks, and enqueuing tasks.
    5. 'PushNotificationWorker': Node.js background process that maps endpoints and dispatches pushes via SNS.
    6. 'SQSTriggerMapping': Links the main SQS queue as a trigger for the worker Lambda.
    7. 'PushApiGateway': An API Gateway HTTP API that proxies all routes.
    8. 'PushApiStage' & 'PushApiRoute': Sets up a default stage ('$default') routing proxy calls to 'PushApiLambda'.
  - Added parameters for Firebase web keys and SNS Platform ARN to allow deploying isolated DEV, PROD, or DEBUG configurations easily.

* Changes.txt (this file):
  - Updated to track SQS DLQ, API Gateway, and CloudFormation automation details.

---

3. ENVIRONMENT PROFILE CONFIGURATION
------------------------------------
By writing a single template.yml file, you can now run a single command in AWS to create three isolated stacks for DEV, PROD, and DEBUG:
- Stack: push-portal-dev (uses dev stage parameters)
- Stack: push-portal-prod (uses prod stage parameters)
- Stack: push-portal-debug (uses debug parameters)

This guarantees consistent deployment across all environments under the AWS Free Tier.
