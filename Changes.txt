CHANGES LOG: ASYNCHRONOUS SQS + LAMBDA UPGRADE
===============================================

This file documents the architectural changes made to transition the AWS Push Notification Portal from a synchronous delivery pattern (Spring Boot calling SNS directly) to an asynchronous, event-driven pattern (Spring Boot enqueuing to SQS -> Lambda consuming and triggering SNS -> CloudWatch Logging).

---

1. ARCHITECTURAL TRANSITION
---------------------------
* Old Flow:
  React Client -> Spring Boot Backend (blocking thread) -> AWS SNS -> FCM -> Browser.
  (Limitation: The backend thread is held open while waiting for third-party endpoints to complete registration and publication).

* New Flow:
  React Client -> Spring Boot Backend -> Amazon SQS Queue (immediate success response)
                                      |
                                      +--> (Automatic SQS trigger)
                                      |
                                      +--> AWS Lambda Worker (asynchronous processing)
                                                    |
                                                    +--> AWS SNS -> FCM -> Browser
                                                    |
                                                    +--> (Execution logs)
                                                    |
                                                    +--> Amazon CloudWatch Logs

---

2. FILE CHANGES LOG (SPRING BOOT BACKEND)
----------------------------------------
* pom.xml:
  - Removed dependency: 'software.amazon.awssdk:sns'
  - Added dependency: 'software.amazon.awssdk:sqs'
  (Decoupled the backend project completely from AWS SNS SDK modules).

* application.properties:
  - Removed property: 'aws.platformApplicationArn' (now handled inside AWS Lambda environment).
  - Added property: 'aws.sqsQueueUrl=${AWS_SQS_QUEUE_URL:}' (directing messages to your SQS queue).

* AwsConfig.java:
  - Replaced the 'SnsClient' Bean with an 'SqsClient' Bean.
  - Implemented thread-safe singleton connection pooling for SQS to reduce latency.

* NotificationController.java:
  - Refactored '/api/register' to return a successful mock response directly back to the React UI, bypassing synchronous registration latency.
  - Refactored '/api/send' to serialize the incoming device token and message text into a JSON string, then enqueues it to the SQS queue using 'sqsClient.sendMessage()'. 

---

3. INFRASTRUCTURE AS CODE (IaC) ADDITION
---------------------------------------
* template.yml (CloudFormation Template):
  - Created a CloudFormation template in the repository root to automate the deployment of your AWS infrastructure.
  - Provisions:
    1. Amazon SQS Queue ('push-notification-queue') with a 30s visibility timeout.
    2. IAM Execution Role ('push-lambda-execution-role') with narrow SQS polling, SNS publishing, and CloudWatch log writing permissions.
    3. AWS Lambda Function ('PushNotificationWorker' on Node.js 22.x) with the message consumption, FCM v1 formatting, and SNS dispatch script embedded inline.
    4. Event Source Mapping trigger linking SQS and Lambda.
  - Dynamically extracts the AWS region from your configured 'PLATFORM_APPLICATION_ARN' to support multi-region queues automatically.
